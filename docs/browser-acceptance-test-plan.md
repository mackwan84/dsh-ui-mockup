# dsh-ui-mockup 浏览器功能验收测试计划与用例

> 文档版本：1.1  
> 编制日期：2026-08-28  
> 适用版本：`0.1.1` 及其后续维护版本
> 测试对象：DSH Web 中的 `dsh-ui-mockup` bundle、双图像 Provider、`ui_mockup` 工具卡片及设置面板

## 1. 结论与测试策略

本轮采用“需求追踪 + 风险驱动 + 真实浏览器端到端”的验收策略。浏览器操作是主验证面，但以下事实不能只凭页面显示判定：Provider 是否真实切换、请求实际命中哪个网关、模型与参考图是否正确下传、凭据是否泄露、资产是否按工作区隔离。因此用例分为三种执行层级：

- **B**：只通过浏览器界面即可判定；
- **B+E**：浏览器操作配合隔离环境、网络故障或测试数据注入；
- **B+L**：浏览器操作配合 DSH 日志、Network、测试资产目录或用户层 patch 佐证。

发布结论必须来自全量 P0、P1 用例执行结果，不能用现有单元测试替代。现有 Vitest 主要在 Node 环境运行，不覆盖真实浏览器、真实 DSH Web、真实云端 API、视觉布局和键盘可访问性。

## 2. 测试目标

1. 验证用户能完成“生成 → 看图反馈 → 修改/选择 → 确认 → 锁定设计规格”的完整闭环。
2. 验证 DashScope 与 Volcengine 均能完成各自声明的生成、参考图与编辑能力。
3. 验证设置面板四页的状态、写入、刷新持久化和异常反馈与服务端事实一致。
4. 验证历史、图片、锚点、凭据和 Provider 配置不会跨工作区串用或泄露。
5. 验证中文/英文、浅色/深色、主流浏览器、窄屏、200% 缩放和键盘操作可用。
6. 验证界面符合 DSH 的视觉令牌、组件、层级、间距和状态规范，并以批准的截图基线控制视觉回归。
7. 验证首次使用、Provider 切换、凭据管理、生成反馈和历史回看等关键任务的可发现性、操作成本、状态反馈和错误恢复质量。
8. 以 WCAG 2.2 AA 为目标验证对比度、键盘、焦点、目标尺寸、缩放、重排和辅助技术语义。
9. 建立明确的准入、暂停、恢复和准出标准，使测试结果可复核、可签字。

### 3.1 需求解释与待确认口径

以下问题不阻止测试启动，但必须在测试结论中单列：

1. `design/spec.md` 是被测用户工作区中的运行时交付物，不要求本插件仓库预先包含该文件。它由 Agent 在用户确认后生成，属于插件 + Agent + 多模态模型的集成验收项。
2. “清空历史”按当前需求只清空 `history.jsonl` 并解除锚点，不等同于删除 `images/` 中的设计资产。若产品希望提供“彻底删除资产”，需另立需求，不能把现行为直接判为失败。
3. 实施计划 §6.5 要求模型可见文本保持中文固定；当前浏览器 UI 文案可切英文。验收时应验证英文 UI 下按钮标签为英文，但发送给 Agent 的确认/选版/修改消息仍符合“模型可见文本固定”的产品口径。若当前实现随 locale 发英文，应记录为需求偏差并由产品确认，而不是按当前实现放行。
4. “确认后自动提炼规格”依赖会话模型具备图像理解能力。纯文本模型下的降级行为应是明确要求用户口述确认，而不是静默声称已完成视觉提炼。

## 4. 范围

### 4.1 本轮范围

- 开发链接安装与发布 tarball/正式包安装；
- DSH Web 启动、插件入口、客户端 bundle 加载；
- 工具生成、图片下载/附件、卡片反馈、设计锁定；
- 设置面板：概览、提供方与模型、生成偏好、生成历史；
- DashScope：线框、高保真、Qwen I2I、Wan 2.7 T2I/I2I、错误处理；
- Volcengine：线框、高保真、I2I、Seedream 指令编辑、错误处理；
- 凭据来源优先级、写入、清除、连接测试、安全；
- 历史、分页、搜索、锚点、工作区隔离；
- 中英文、浅深色、响应式、缩放、键盘和基础读屏语义；
- DSH 视觉令牌、原生组件、信息层级、状态设计、视觉回归基线；
- 首次使用、Provider 切换、凭据管理、生成反馈、历史回看等关键流程的 UX 质量；
- WCAG 2.2 AA 对比度、目标尺寸、焦点、重排、文本间距和状态可感知性；
- Chrome、Edge、Safari、Firefox 的关键流程；
- 429、401、403、5xx、超时、断网、坏图片、超大图片、路径逃逸。

### 4.2 不在本轮范围

- 生成图片的艺术审美评分；只验证与提示词、布局目标、语言和尺寸的基本一致性；
- 云供应商模型自身的生成质量稳定性 SLA；
- DSH 与本插件无关的通用聊天、模型、插件管理功能；
- mask 局部重绘；当前两个 Provider 均未声明支持；
- 供应商国际站，除非本次发布声明支持对应 Base URL。

| 等级    | 定义                                                           | 示例                                                   |

| S0 阻断 | 无法安装/启动/进入插件；数据或密钥严重泄露；跨工作区任意读文件 | 插件导致 DSH Web 无法启动；Key 出现在页面或日志        |

## 9. 准入、暂停、恢复与准出

### 9.1 准入条件

- 需求 R-01～R-15 已冻结，待确认项已指定裁决人；
- DSH Design Token、原生设置页参考或产品批准的视觉基线至少提供一种；缺少独立视觉基准时只能报告观察，不得判定“符合视觉规范”；
- 提供唯一构建号/提交号、安装包和变更说明；
- 两套有效 Provider Key 与隔离 DSH_HOME 可用；
- T0 构建、测试、打包、安装门禁通过；
- 可观察 Network、DSH 日志、用户 patch 和隔离资产目录；
- 网络故障/状态码注入方案可用，且不会影响生产账号。

### 9.2 暂停条件

- 冒烟 P0 任一失败；
- 测试环境状态不可信，例如页面 Provider 与日志不一致；
- 有效 Key 全部不可用或供应商大面积故障；
- 发现 S0，或同一根因导致 20% 以上用例阻塞；
- 测试数据可能污染个人真实 DSH_HOME 或泄露密钥。

### 9.3 恢复条件

- 阻断根因已确认并提供可唯一识别的新构建；
- 环境已恢复、测试数据已重置；
- 原失败用例复测通过；
- 相关域冒烟通过后再恢复全量测试。

### 9.4 准出条件

- P0：100% 通过；P1：≥95% 通过且未通过项均有产品/研发书面风险接受；
- 无未关闭 S0/S1；S2 必须有修复计划或明确风险接受；
- DashScope 与 Volcengine 各至少一次真实生成成功；DashScope Qwen/Wan 2.7 I2I、
  Volcengine I2I 与 Seedream 指令编辑成功；
- 双向切换与实际 `providerId`、请求域名、模型一致；
- Chrome 全量通过，Edge/Safari/Firefox 关键流程通过；
- 320px、200% 缩放、键盘关键流程通过；
- VIS、UX、A11Y 域 P0 全通过；P1 偏差均有截图证据和设计/产品裁决；
- 视觉基线变更经过设计负责人批准，不得通过更新基线掩盖回归；
- 密钥无页面/日志/Network/报告泄露，跨工作区与路径逃逸验证通过；
- 最终报告包含执行构建、环境、用例统计、缺陷、遗留风险和签字。

## 10. 通用执行与证据规范

每条用例记录：构建号、浏览器/版本、OS、locale、主题、视口、Provider、Key 来源、工作区、执行人、时间、结果、缺陷号。

证据最低要求：

- 页面结果：操作前后截图；竞态、热重载、长任务使用录屏；
- 网络结果：记录 URL 域名、状态码、时序、请求模型等非敏感字段；清除 Authorization、Cookie、完整提示词中的业务敏感信息；
- 服务事实：记录 `providerId`、用户 patch 的两个 `disabled` 行、日志错误码；不得附 Key；
- 资产结果：记录相对路径、文件名、大小、魔数和工作区 slug；不把真实业务图片上传到缺陷系统；
- 缺陷复现：最小步骤、实际/预期、首个异常时间点、影响范围、附件、是否可稳定复现。

### 10.1 视觉与 UX 判定基准

视觉判定必须使用独立基准，优先级为：正式 DSH 设计规范/Design Token → DSH 原生同类页面与组件 → 设计负责人批准的参考截图 → 本轮批准的基线截图。当前实现本身只能作为被测对象，不能反向定义正确标准。

量化基准：

- 普通文本与背景对比度至少 4.5:1；大文本至少 3:1；关键控件边界、焦点和非文本状态至少 3:1；
- 指针目标至少容纳 24×24 CSS px，或满足 WCAG 2.2 的间距/等价入口例外；产品内部可采用更高的 44×44 CSS px 触控舒适目标，但不得把它误写成 AA 最低要求；
- 普通内容在等效 320 CSS px 宽度下应重排且无非必要双向滚动；200% 文本缩放、400% 等效重排不丢失内容或功能；
- 所有颜色、字号、字重、圆角、间距、边框和状态色以批准 Token/组件值为准；不得用“肉眼接近”代替测量；
- 结构、内容和状态差异零容忍；字体抗锯齿、亚像素渲染和浏览器原生控件差异必须进入白名单，不能设置一个统一像素差异百分比直接放行。

视觉基线截图矩阵至少覆盖：

| 维度      | 取值                                                                    |
| --------- | ----------------------------------------------------------------------- |
| 页面/组件 | 设置四页；单图/多图卡片；反馈展开；历史分页/锚点；Provider 与凭据各状态 |
| locale    | 中文、英文                                                              |
| 主题      | 浅色、深色                                                              |
| 视口      | 1440、1024、768、375、320 CSS px                                        |
| 状态      | 默认、加载、空、成功、警告、错误、禁用、长内容                          |

基线更新流程：先解释差异的需求来源，再由设计负责人批准，最后更新基线并保留前后对比。禁止因为测试失败而直接覆盖基线。
