## 1. 执行范围与判定口径

**应用主题统一为“客户通 CRM 系统”，唯一验收工作区为 qa-ui-mockup-crm。** 所有生成、修改、参考图、历史、规格文件和故障数据都归属该工作区；客户、联系人、金额与跟进记录均为虚构测试数据。工作区内可创建多个验收会话，不能把不同会话当作不同工作区。原跨工作区隔离用例 HIS-15 保留追踪，但因本轮单工作区约束不执行，也不宣称跨工作区隔离已通过。

测试入口是 **DSH Web → 设置 → UI 草图**，包含“概览 / 提供方与模型 / 生成偏好 / 生成历史”四页，以及会话中的 ui_mockup 卡片。生成通过会话输入触发，确认、选版、修改、设锚通过卡片操作完成。

正式视口基线为桌面 **1024×800、1440×900 CSS px**。Mobile 是生成图片的目标平台，不表示宿主设置窗口承诺支持手机宽度。768/375/320px 作为范围外观察，不沿用旧总计划的全端发布门禁。

### 1.2 必须遵守的边界

1. **耗时不是服务端进度。** 计时起点是持久化的工具调用事件时间，包含生成、重试、图片下载等尚未返回最终结果的等待；不是剩余时间，也不能证明模型仍在计算。刷新或切换会话导致卡片重建时应按同一调用时间继续累计；仅旧数据异常缺少事件时间时回退到本次卡片挂载时间。
2. **三层时限分开。** 火山 requestTimeoutMs 默认 300000ms，针对每次同步 HTTP 请求；“生成偏好 → 轮询超时”默认 10 分钟，主要下传百炼异步轮询；工具注册时限为 900000ms。不能通过把面板轮询改成 1 分钟来复现火山同步超时。火山多图为串行请求，整张工具卡可以累计超过 5 分钟。
3. **文字质量分两层验证。** 提示词是否包含约束可确定验证；模型是否画出完全准确中文是抽样观察。不能用一张幸运样本宣称解决乱码，也不能因出现一个非关键错字就判定提示词分支未生效。
4. **指令编辑有独立提示词。** baseImage + editNote 走编辑，真正下发的 prompt 是 editNote，不经过三类生成提示词模板；不要要求编辑请求自动包含新增文字密度约束。
5. **按钮位置以 0.2.0 为准。** 设为锚点入口在会话卡片；历史页提供解除锚点、打开原图和前往锚点所在页。卡片图片本身是标注入口，“打开原图”已移入标注弹窗底部。多图卡片的“确认采用这版”和普通修改意见默认针对首图；点击哪张图片就标注哪张。
6. **历史容错不是文件修复。** 不可读历史降级为空列表；不会提示“已经修复”，不会自动修复损坏文件。清空历史清除元数据并解除锚点，保留图片资产。有效记录按文件行逆序展示，本轮测试数据按时间递增写入。
7. **规格锁定是 Agent 集成行为。** 按钮发送消息后，由 Agent 生成 design/spec.md；插件本身没有独立“锁定”开关。必须使用可读图的会话模型测试视觉提炼，纯文本模型另测降级。
8. **模型反馈语言固定。** UI 按钮随界面语言切换，但确认、选版和编辑意见发送给模型时固定为中文；英文界面必须同时核对英文按钮和中文模型消息。
9. **标注不等于像素级局部编辑。** 0.2.0 只发送归一化坐标文本与意见，不发送合成标注图附件；百炼当前回退整体重生成，火山为整图指令编辑，均不承诺“只改圈选区域、其余像素不变”。
10. **方向稿不是第三种 fidelity。** 工具仍只有 `wireframe` / `high-fidelity`；方向稿是 `high-fidelity + fastPreview=true`。精修必须保持同一描述并去掉 `fastPreview`，不得把方向稿历史标签当成已确认设计。
11. **本手册定义待执行用例，不复用旧结论。** `docs/releases/v0.2.0.md` 中既有 25/25 前置校验只能作为历史证据；本轮全量执行必须逐项形成新的执行记录。

### 2.2 公共操作与结果记录

- **S（设置入口）**：打开测试 URL，选择指定工作区/会话，打开 DSH 设置，点击“UI 草图”，再点击用例指定页签。
- **G（生成操作）**：关闭设置，在会话输入框粘贴下面的调用模板，替换 JSON 参数并发送；确认实际触发 ui_mockup，核对实际参数后才开始判定。不允许只把 Agent 的文字回复当成调用成功。
- **N（标注操作）**：点击目标图片进入“标注修改区域”；按用例选择工具、颜色、缩放，完成圈选和意见后提交；必须核对最终发送给 Agent 的消息正文。
- **R（方向稿操作）**：使用 D12，显式传 `fidelity="high-fidelity"` 与 `fastPreview=true`；精修时点击方向稿卡片“按这版精修”，再核对下一次工具实际参数不含 `fastPreview`。
- **H（历史刷新）**：进入“生成历史”；若已在该页，先切“概览”再切回。等待列表请求完成；历史写入是异步操作，不将工具完成瞬间的一次旧快照直接判为丢失。
- **A（解除锚点）**：进入历史，若提示锚点在其他页，点“前往”，然后点锚点行的“解除锚点”；回到第 1 页。无锚点则跳过。
- **恢复**：每条用例独立执行。通过浏览器恢复用例改动的提供方、偏好、语言、主题和锚点；故障环境由负责人复原；清空、覆盖密钥只对隔离环境执行。需要复用上条用例产物时在前置条件中明确说明。

生成模板：

```text
这是 QA020-CRM 验收，唯一工作区为 qa-ui-mockup-crm。请调用一次 ui_mockup，严格使用以下参数；不要补充 model、
reference、baseImage、editNote 等未列出的参数，不要开始实现代码。
若工具失败，请停止并保留原始错误，不要自动重试或改用其他工具。
参数：
{"description":"替换为下列指定 CRM 测试文案","fidelity":"wireframe","platform":"web","count":1}
```

fidelity 是必填工具参数；“保真度偏好”不等于工具可省略 fidelity。省略 model 才能验证模型分层默认。方向稿必须同时满足 `high-fidelity + fastPreview=true`。用户自然语言与实际调用不一致时，记录为 Agent 调度偏差并重新构造正确调用，不将无效测试算通过。若模型始终拒绝非法参数负测，记为“阻塞：未触达工具校验”，交由集成测试补证。

对已生成图片传 reference 或 baseImage 时，统一使用 **design/images/真实文件名**（例如 design/images/mockup-时间戳-随机段-1.png）；工具结果只向模型提供该语义路径，插件会将其转换到对应资产库。不要把图片复制进项目来绕过路径校验。D05-A/D05-B均指这样引用的真实图片。

每条用例至少留存：前置截图、关键状态截图或录屏、实际结果、执行子项、缺陷/阻塞原因。计时留**从工具调用事件开始的录屏及外部秒表**，刷新前后记录同一调用标识；请求和错误码留脱敏原始工具结果；历史留搜索条件、条数、页码与记录标题。不得只截 Agent 概括性回复。

密钥写入请求本来就需向 DSH 发送用户输入值；KEY-06 排查的是响应、日志、历史和持久回显泄露，不要求合法写入请求体中“没有密钥”。证据导出前遮蔽写入请求体和 Authorization，不保存真实 Key。

## 3. 优先级与公共断言

- **P0**：发布阻断主流程或本轮核心修复；**P1**：必须执行的边界与回归；**P2**：扩展观察。
- 每个表格参数组合是一项独立执行记录，例如 TXT-01/DashScope 与 TXT-01/Volcengine 不能合并为一个“通过”。
- 所有成功生成都核对实际工具成功、图片可显示、历史可回看；所有失败都核对无虚假成功、无持续生成态、错误可保留、健康条件恢复后能再次操作。
- 成功耗时不是硬性性能 SLA。真实服务超过常见时间应记录耗时与上下文；只有确定超出已配置时限却未按约定结束，才归入相应超时问题。
- 前台稳定页面的计时观察允许录屏采样/事件循环带来的约 2 秒偏差；分钟进位格式必须正确。后台标签页允许节流，恢复前台后应基于实际时间追上；这些是本轮测试观察容差，不是对外产品承诺。
- “停止计时”判定为终态后至少观察 5 秒，不再出现生成耗时标签；内部计时器是否彻底释放不能仅凭截图证明，可由现有组件测试补证。

### 7.2 抽样与对比

每家提供方对 TXT-01、TXT-02、TXT-03 各取 **3 张独立样本**，即默认模型组合至少18张；复用真实生成用例的同条件样本，避免重复消耗。每张单独记录结果，不挑选最好的一张替代整组。Wan2.7各组合至少1张功能样本；出现质量异常再补2张复核。

若需要宣称“相对0.1.3改善”，在0.1.3与0.2.0分别使用相同模型、描述、style、尺寸、参考图和数量，各取至少3张，并列出两组记录。固定随机种子仅在实际接口支持且已经使用时填写；云模型和随机性会限制归因。缺少基线或样本不足时结论写“新增约束已验证；视觉改善证据不足”，不填写没有依据的改善百分比。

## 8. 执行顺序、覆盖统计与回归选择

本手册共 **141 条逻辑用例：P0 56 条、P1 83 条、P2 2 条；其中 HIS-15 因用户限定单工作区而不适用，本轮可执行范围为140条（P0 55、P1 83、P2 2）**。参数组合、浏览器组合、语言/主题/视口、故障变体和质量复采都要展开为独立执行项，因此实际执行数大于141。

### 9.3 发布建议门禁

1. 五包0.2.0构建明确，干净安装与0.1.3升级有证据。
2. 本轮适用的P0全部通过，且没有未解决的S0/S1；HIS-15的不适用须明确披露，不能声称跨工作区已验收；P0缺环境的“阻塞”不能算通过。
3. P1全部有执行结论；遗留失败/阻塞逐项注明影响、规避方式和接受人。存在遗留项时只能提出“有条件通过”，不能写“全部通过”。
4. ANN-01～ANN-18与FPR-01～FPR-12全部通过；标注消息目标图、归一化坐标、原图编辑链路、模型优先级、精修参数及历史方向稿筛选均有原始证据。
5. 两家提供方真实线框/方向稿/高保真/多图/I2I、火山编辑均有成功样本；桩结果只能证明逻辑，不能证明云服务真实可用。
6. 方向稿与精修各至少3次耗时样本有记录；若收益不足不阻断功能发布，必须在发布结论中披露，除非负责人事先把性能阈值签为硬门槛。
7. 三模板、秒/分进位、成功/失败/取消停表、首部/正文超时、默认300s、损坏历史与不可读历史均有专项证据。
8. 正式桌面范围内无新增阻断；UI/UX验收视图各维度有结论；质量检查、canvas键盘限制与纯文本模型降级明确；没有把本地计时描述为服务端进度验证。
9. 恢复测试提供方、三档模型、生成偏好、语言/主题和锚点；截图/日志不含Key；故障场景关闭，历史/资产清理范围可追溯。

本手册定义用例和验收方法；0.2.0最终结论记录在发布检查清单中。
