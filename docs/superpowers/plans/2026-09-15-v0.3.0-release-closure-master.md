# v0.3.0 P0 Release Closure Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将 v0.3.0 验收台账中 67 条未关闭 P0 收敛为 94 条通过、1 条不适用、0 条失败/阻塞/未执行，并形成进入正式发版门禁所需的原始证据。

**Architecture:** 以不可变候选提交为中心，使用多个隔离 `DSH_HOME`、确定性 F01～F17 故障服务、三家真实 Provider 和 Codex 内置浏览器生成证据。五个批次分别拥有独立环境与退出条件，最终由单一台账汇总，不从组件测试外推浏览器通过。

**Tech Stack:** pnpm、Vitest、Node.js HTTP fixtures、DSH Web、Codex In-app Browser、Markdown/JSONL、npm pack/dry-run。

**Spec:** `docs/testing/v0.3.0/browser-cases.md`

## Global Constraints

- 候选基线冻结为启动时 `develop@b93b3bf5f9178e69b57e9af36583b19d1675ccd4`；任何缺陷修复产生新候选后，受影响批次必须重新验证。
- 所有运行制品写入 `.artifacts/v0.3.0-release-closure-20260915/`，不得提交 Git。
- 每个破坏性或故障场景使用独立 `DSH_HOME` 和工作区，不读取或改写个人 DSH 配置、历史、锚点和图片。
- 真实凭据只能通过专用环境变量或隔离 DSH 密钥存储注入；报告、命令输出和截图不得包含值。
- 状态只能是通过、失败、阻塞、不适用、未执行；缺一项必需断言不能记通过。
- 组件测试、命令行 live 和旧截图不能替代 P0 浏览器证据。
- 不推送、不创建 MR、不发布 npm、不创建标签或 GitHub Release，直到用户对对应外部动作再次明确授权。
