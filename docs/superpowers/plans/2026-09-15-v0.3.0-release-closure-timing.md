# v0.3.0 Timing And Error P0 Closure Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 关闭 ERR、TIM 共 15 条未关闭 P0。

**Architecture:** F01～F06 服务为每个场景提供独立路由和请求时间线；浏览器卡片状态与代理收到请求、连接关闭、重试次数联合判定。

**Tech Stack:** Node.js HTTP server、AbortSignal、DSH Web、Codex Browser、JSONL timing trace。

**Spec:** `docs/testing/v0.3.0/browser-cases.md` 的 ERR、TIM 与 F01～F06。

## Global Constraints

- 所有时间以故障服务收到请求的单调时间为起点，浏览器总耗时只作辅助。
- 4999ms 等抖动边界不能单样本判定；使用 3000ms 成功与持续挂起形成稳定对照。
- 火山同步请求默认 300000ms 超时必须真实等待一次；百炼异步轮询默认 600000ms（10 分钟）必须按各自语义验收，二者不得互相替代。
- 自动重试与手工重试必须由上游请求计数区分。
