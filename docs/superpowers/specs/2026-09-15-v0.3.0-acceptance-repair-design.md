## 1. 目标与完成口径

本轮目标不是把阻塞项改写为通过，而是把两份验收报告中的问题按事实分成三类并分别处理：

1. 修复已确认的产品缺陷，并以自动化测试和真实浏览器定向复测证明修复有效；
2. 修正报告统计、状态归类和证据链，使 197 条逻辑用例一一对应且状态互斥；
3. 为仓库可控的 F01～F17 场景准备隔离故障环境并重新执行，外部能力缺口继续如实阻塞。

完成时必须满足：三个产品缺陷均有红绿测试记录；全仓校验通过；受影响浏览器用例复测；197 条台账统计闭合；没有用旧版本结论、组件测试或命令行结果冒充浏览器通过。

## 2. 范围与非目标

### 2.1 本轮范围

- OpenAI 兼容成功响应缺少 `model` 时的结果与历史模型空值；
- 单页历史不显示总条数；
- OpenAI 兼容方向稿点击“按这版精修”后，Agent 首次调用错误携带 `reference`；
- 首轮执行报告的统计不闭合、状态重叠、证据不足和严重度偏低；
- F01～F17 中可通过本仓代码、临时 Provider 桩、隔离 `DSH_HOME` 和 Chromium 浏览器关闭的项目。

### 2.2 非目标

- 不修改 DSH 宿主以增加英文界面；
- 不安装或伪装 Edge、Safari、Firefox，也不把 Chromium 结果复制为跨浏览器通过；
- 不执行 npm 发布、Git 标签、GitHub Release、远端推送或正式发版；
- 不把 Provider 桩、浏览器截图、日志和执行报告提交 Git；
- 不扩大 OpenAI 兼容最小子集，不新增参考图或编辑端点支持。

## 3. 产品修复设计

### 3.1 OpenAI 兼容模型回落

`OpenaiCompatImageProvider.generate` 已解析出最终请求模型，`postImages` 也保留请求体。成功响应处理采用以下规则：

1. `data.model` 是非空字符串时，以响应模型为准；
2. 响应未提供有效模型时，回落到本次请求体的 `model`；
3. 不从面板、环境变量或全局状态二次推断，避免请求与历史不一致。

这样工具结果、历史 `model` 和用户实际请求保持一致，同时兼容会返回模型名的网关。测试先覆盖“成功响应无 model”并观察现状返回空串，再实施最小修复；已有“响应带 model”断言继续保护优先级。

### 3.2 单页历史总条数

历史服务端继续返回 `total/page/pageSize`，只调整客户端呈现：

- `共 N 条`独立于分页按钮显示；`total=0`、单页和多页均可见；
- 上一页、页码、下一页仍只在 `totalPages > 1` 时显示；
- 搜索、方向稿过滤和迟到响应防护继续使用现有状态流，不新增计数来源。

组件测试覆盖 `total=0/1/5/6`，验证单页有总数、多页有总数与分页、空态不沿用旧总数。

### 3.3 方向稿精修消息

按钮出现条件保持不变，仍仅由 `high-fidelity + fastPreview=true` 决定。固定中文消息改为明确的调用约束：

- 文件名只用于识别被确认的方向稿，不得作为 `reference`、`baseImage` 或 `editNote`；
- 下一次调用复用原 `description`，使用 `fidelity=high-fidelity`；
- 省略 `fastPreview/reference/baseImage/editNote`，让精修档按同一描述重新生成。

中英文 UI 继续发送同一固定中文模型消息。组件测试先断言新消息并观察旧文案失败，再修改词条；浏览器复测要求点击一次后首次工具调用即符合约束，不接受“先失败再恢复”覆盖首次断言。

## 4. 隔离故障环境设计

### 4.1 复用与存放

复用 `.artifacts/v0.2.0-browser-run-2026-09-08/fault-server.mjs` 的已有 F01～F12 路由，在 `.artifacts/v0.3.0-browser-run-20260915/` 创建本轮副本并扩展 F13～F17。根据文档治理要求，所有 Provider 桩、补丁快照、响应、日志和截图均留在 `.artifacts/`，不得提交 Git。

### 4.2 隔离边界

- 每次运行创建独立临时 `DSH_HOME`、工作区和端口；
- 只使用虚构凭据，不读取 `~/.dsh/.credentials.yaml`；
- 不修改个人 `~/.dsh/cordis.patch.yml`、当前 CRM 历史、锚点或设计资产；
- 每个场景记录入口、配置、预期窗口、请求次数、恢复动作和快照校验和；
- 测试结束停止故障服务并保留证据，不删除用户原有数据。

### 4.3 场景覆盖

- F01～F06：慢成功、首部/正文挂起、取消、默认时限、错误与限流；
- F07～F12：历史损坏、设置异常、图片异常、标注图片与方向稿历史；
- F13：三提供方补丁读取、写入、HMR pending 和配置重述；
- F14：模型列表重复、非法项、鉴权、HTML、重定向、网络和超时；
- F15：兼容生成的 b64、url、混装、非法条目和畸形 2xx；
- F16：400/401/403/429/500/503、空体、连接失败、重定向和挂起；
- F17：公开 URL、404、慢下载和需鉴权下载的已知限制。

## 5. 验收与证据流

执行顺序固定为：

1. 定向复测 `GEN-01/FPR-01/FPR-03/HIS-11/HIS-12`；
2. 执行三个修复直接影响的相关用例组；
3. 在隔离环境执行可关闭的 P0；
4. 执行 Chromium 下其余可执行项目；
5. 重算 197 条台账并形成准出结论。

浏览器使用 Codex In-app Browser 的真实点击、键盘和拖拽通道。DOM 读取只用于核对候选值、尺寸、滚动量与可访问属性，不能替代视觉证据。每个 P0 执行项至少保留：前置状态、操作后截图或录屏、脱敏请求/结果、实际参数、状态、恢复情况和候选提交。

逻辑用例状态只能是“通过 / 失败 / 阻塞 / 不适用 / 未执行”。子项未完成可写入依据栏，但整条不能使用“部分通过”。

## 6. 验证与提交策略

三个产品缺陷分别按 TDD 和原子提交处理：

1. `fix(image-openai-compat): 响应缺少模型时回落请求模型`
2. `fix(tool-ui-mockup): 单页历史显示总条数`
3. `fix(tool-ui-mockup): 约束方向稿精修调用参数`

每个提交包含对应源码、自动化测试和必要的当前行为文档。完成后运行：

```text
pnpm test
pnpm typecheck
pnpm lint
pnpm format:check
pnpm build
```

浏览器报告和状态台账在 `.artifacts/` 更新，不进入 Git。若长期产品行为或架构事实发生变化，同一代码提交同步更新 `docs/guides/`、`docs/architecture/` 或 v0.3.0 测试资料。

## 7. 风险与停止条件

- 若任一修复连续三次假设失败，停止继续补丁并重新评估模块边界；
- 若故障桩行为与真实 Provider 契约冲突，以当前代码契约和已核对技术事实为准，不为迁就旧桩修改产品；
- 若隔离 DSH 实例无法使用当前候选构建，保留阻塞并报告启动链路，不切回个人环境破坏数据；
- 若浏览器证据无法持久化，任务内截图只能作为辅助证据，发布门禁仍保持阻塞；
- 外部能力缺失不得通过降低预期、复用旧截图或复制其他浏览器结果关闭。
